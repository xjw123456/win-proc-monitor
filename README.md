# 进程性能监控工具（Windows 10 / 11）

手动启停、每 2 秒采样一次，记录某个应用进程（可按进程名聚合全部实例）的 CPU 与内存占用，
停止后自动生成 Excel 原始数据、HTML 性能报告与 Markdown 摘要，并给出「CPU 是否超标 / 内存是否超标 /
内存是否有正常释放趋势」三项判定。

> 所有产物都写在**工具根目录下的 `output\`** 里，按 `进程名_年月日_时分秒` 分子目录归档。

---

## 一、快速开始

1. 双击 `启动.bat`（优先使用 `C:\Program Files\Python39\python.exe`，找不到则用 PATH 上的 `python`）。
2. 左栏「目标进程」里点选要监控的进程（搜索框可筛选，默认按进程名聚合所有实例）。
3. 点 **开始**；需要中断一段就点 **暂停**，再点 **继续** 接上（暂停期间不采样）。
4. 点 **停止**：工具会停止采样并自动生成三个文件，弹窗会给出产物目录。

命令行方式（适合自动化 / 无人值守）：

```bat
python app.py --list                       :: 列出可监控的进程
python app.py --cli chrome.exe -d 60        :: 采集 60 秒
python app.py --cli chrome.exe -d 300 -i 2  :: 间隔 2 秒（默认）
python app.py --cli --pid 1234 -d 60        :: 指定 PID（不聚合同名实例）
```

## 二、产物说明

每次监控生成一个目录 `output\<进程名>_<yyyyMMdd_HHmmss>\`：

| 文件 | 内容 |
|---|---|
| `01_原始数据.xlsx` | 5 个 sheet：00_监控说明 / 01_原始数据（前 3 列与任务管理器一一对应，共 17 列）/ 02_统计汇总 / 03_判定结果 / 04_图表（双轴折线） |
| `02_性能报告.html` | 单文件报告，内联 SVG 时序图，双击打开，Ctrl+P 可直接存 PDF |
| `03_性能报告摘要.md` | 结论 + 关键数据 + 判定明细 + 建议，便于贴到工单/IM |
| `meta.json` | 采集元数据与阈值快照（PID 列表、起止时间、口径来源等） |

## 三、数据口径（与任务管理器对齐）

| 指标 | 本工具口径 | 对应任务管理器 |
|---|---|---|
| CPU 占用率 | `Δ(进程全部线程 CPU 时间) ÷ Δ墙钟 ÷ 逻辑处理器数 × 100` | 「进程」页 CPU 列（同名实例求和） |
| 区间 CPU 时间 | 两次采样之间实际消耗的 CPU 时间（ms） | 无直接列，用于还原「占用大小」 |
| 等效核数 | `CPU% × 逻辑处理器数 ÷ 100`，即「相当于吃满几个核」 | 「性能」页 CPU 曲线可对照 |
| 累计 CPU 时间 | 进程启动至今累计 CPU 时间 | 「详细信息」页「CPU 时间」列 |
| 内存（主口径） | **私有工作集**（Private Working Set） | 「进程」页「内存」列 |
| 内存使用率 | 私有工作集 ÷ 物理内存总量 × 100% | 无单进程百分比，与「性能」页内存百分比同口径 |
| 工作集 / 提交大小 | 总工作集 / 提交大小，作辅助列 | 「详细信息」页对应列 |

抽检一致性判定标准：同一时刻 CPU 差 ≤ 2 个百分点、内存差 ≤ 1%（或 ≤ 2 MB），10 次抽检 ≥ 9 次达标。
差异来源：任务管理器自身 1 秒刷新窗口、CPU 显示取整、内存毫秒级抖动。

### 原始数据表怎么和任务管理器对号入座

`01_原始数据` 第 3 行是表头，前 3 列就是任务管理器「进程」页看到的那三列：

| 数据表列 | 任务管理器里的位置 |
|---|---|
| A 列 `采样时间` | 右上角「上次更新时间」对应的时间点 |
| C 列 `CPU(%)` | 「CPU」列（同名多开已求和） |
| D 列 `内存(MB)` | 「内存」列（私有工作集） |

其后是「占用大小」的补充与精确值：`区间CPU时间(ms)`（该窗口实际吃掉的 CPU 时间）、
`累计CPU时间`（对应「详细信息 → CPU 时间」）、`等效核数`、`私有工作集(MB)`、`内存占用率(%)`、
`工作集`/`提交大小`/`线程数`/`句柄数`/`实例数`、`内存来源`、`备注`。

### 内存权限问题（已解决）

优先用进程句柄直读（`PROCESS_MEMORY_COUNTERS_EX2`）。若句柄被系统拒绝（受保护进程 / 权限不足），
自动改用 `NtQuerySystemInformation(SystemProcessInformation)` 的系统进程表——这正是任务管理器
「性能」页汇总进程内存所用的同一条通道，**普通权限即可读取全部进程**，私有工作集数值口径不变。
数据表「内存来源」列会标 `句柄直读` / `系统通道`，报告里同步注明。该通道不返回工作集与提交大小，
对应两列留空，不做任何估算填充。

### 界面实时读数

主界面右侧除目标进程的 4 张统计卡外，还有一条「本机实时」信息带：
`CPU x%`（GetSystemTimes 差分，与「性能」页 CPU 曲线同口径）与
`内存 x%（已用 / 总 MB）` 及颜色进度条（与「性能」页内存百分比同口径）。

## 四、判定标准（可在 `config.json` 调整）

**CPU**：均值 ≤50%，P95 ≤70%，峰值 ≤90%（>95% 直接不通过），≥80% 连续 ≤30 秒。
**内存**：峰值 ≤ 物理内存 80%（>90% 不通过），期末较基线增长 ≤20%。
**释放趋势**：监控期内出现「涨幅 ≥ max(50 MB, 基线 5%) 的峰值 + 120 秒内回落到基线 +15% 带内」记为一次有效释放；
结合释放次数、期末/基线、斜率与 R²，给出「正常释放 / 疑似泄漏 / 持续增长未见释放 / 有释放但整体上移 / 内存稳定」。

三档结论：**通过 / 关注 / 不通过**（样本 < 30 条时释放趋势为「样本不足」，不下结论）。
最终结论取三项中最严的一档。

## 六、常见问题

**Q：为什么 CPU 与任务管理器差 0.5 个百分点左右？**
任务管理器是 1 秒窗口 + 取整显示，本工具是 2 秒窗口精确值；把间隔改成 1 秒并对比同秒数据可进一步收窄。

**Q：内存为什么比「详细信息」页的「工作集」小？**
「进程」页显示的是私有工作集（不含共享内存），「详细信息」页的「工作集」含共享部分，两者本就不同；报告里的「工作集」列可与后者对照。

**Q：进程中途被关闭了怎么办？**
工具会标注「目标进程已退出」并照常生成报告，已采集的数据不会丢。

**Q：需要管理员权限吗？**
普通权限可监控绝大多数用户态进程；部分系统/受保护进程会因权限不足读不到内存，工具会明确提示。

## 八、已知限制

| 限制 | 说明 |
|---|---|
| 无单进程内存百分比对照 | 任务管理器不给单进程内存百分比，本工具的「内存占用率」= 私有工作集 ÷ 物理内存总量，与「性能」页同口径 |
| CPU 抽检需同窗口对齐 | 任务管理器 1 秒刷新且取整，抽检时请在同一秒内刷新对比，否则可能出现个位数百分点的假差异 |
| 只统计「当前存在」的实例 | 聚合期间的实例中途退出后不再计入，报告会提示实例数变化 |
| 长稳未覆盖 30 分钟以上 | 已跑 3 分钟 / 185 秒无异常，正式长时间使用前建议先跑一次 `--cli chrome.exe -d 1800 -i 2` |
| 系统保护进程的内存来源 | 句柄被拒时自动改用 `NtQuerySystemInformation` 系统进程表（普通权限可读），
「内存来源」列会标注「系统通道」；该通道不返回工作集 / 提交大小，这几列留空，私有工作集口径仍与任务管理器一致 |

自检结论与证据见 `output\\06_验收自检报告.md`（A1–A7 达成，A8 建议补 30 分钟长跑）。
